# Agent evidence and observation contract

**Stage I (source-hidden):** every mode receives the complete `TLUL_PROFILE.md`, sanitized initial simulator symptoms, identical ability to query accepted PIN records, and the same tool/evidence budgets. No fault-bearing RTL, clean source, mutation diff, private manifest, older study transcript, repository history or generator is available.

- **A:** ordinary accepted pin samples and bounded waveform/log queries.
- **B:** A plus real current-Xezim `XEZIM_VALUE_TRACE` writer/value records; the match count and actual lines must be verified.
- **C:** B plus bounded **native** observation only after it has been ported and qualified on the pinned Xezim checkout. A Python-derived external A/D correlation adapter is available in this starter for engineering demonstration, but this adapter is *not* a native observer and may not be scored as the native C condition.
- **D:** C plus a **subject-selected** controlled experiment: choose input target, timing, duration and a specific prediction before executing SV force/release; compare the real baseline, experiment, inert-wire control and idempotent request-throttle-zero control (orthogonal when the selected active target is D-ready). All four runs and costs count. The agent does not select or modify an oracle output.

**Stage II (source-reveal):** after Stage I's immutable hash is stored, reveal the same fault-bearing source to every mode. Accept one patch and grade in a separate process on original, unseen, and adversarial legal traffic. Mechanism, component, patch policy, executable repair, false-positive rate, evidence bytes, tokens, and wall time are **separate** metrics.

## Native integration boundary (hard gate)

Pinned main on 2026-10-30: `80f00d354fc68c436569b12b6d4e175ef105a652`. The previously developed `src/compiler/simulator/dvcon_observation.rs` exists at published research commit `a2e29b76262ce3862759a93e1fe9a8341275c397` but **does not appear at its old path on this newer main**. A qualified native C/D implementation therefore requires an explicit port and executable test. Preserve its provenance and avoid modifying default simulator scheduling/NBA behavior.

The supplied `NATIVE_RECIPE_PORT_REQUIRED.json` uses the exact archived Rust research rule fields, but it is **NOT validated against this latest binary**. Confirm schema and actual hierarchical signal objects against the port, then record output, manifest, stats and hashes. The pretrigger ring stores samples from explicit hooks. It is not an automatic all-write history, state snapshot, native arbitrary plugin ABI or formal causality proof.

## Source-visible and unavailable provenance

An external adapter can join `A.source` to `D.source` based on accepted pins only. It must never invent UVM transaction IDs, physical agent IDs, scheduling region, internal writer or causality. The newer existing Xezim value trace may report committed-writer source locations; any fields absent from the native research observer are recorded as unknown, not backfilled from a different evidence channel without attribution.

A run where C/D used only `semantic_external.json` may be included as a separate **external-adapter showcase**, but **NOT** as a primary native-observation effect estimate.
